# Common completion guard amendment

Authorized November 11, 2026 after the native-only parent sweep's verified negative result. The original protocol and native-only results remain unchanged historical artifacts. This amendment and `completion-guard-plan-v1.json` govern the next development qualification/selection job; they do not retrospectively make either native-only sweep pass.

Both native and agent execution now use one common serving completion rule: after ANN/policy completion, replace a short result with exact filtered top-k. Do not append partial candidates, relax recall/completeness requirements, or special-case known query IDs/filters. Corrupt/ineligible output remains an integrity failure. The parent is explicitly a hybrid, not unmodified native. Primary intervention comparison will be against the selected guarded parent; tuned static baselines and all future agent candidates must use the same guard source/version. Retain unguarded native640 and the native-only extended-effort sweep as scoped historical comparators.

All six scalar filters, the unfiltered control, original physical graph, cosine metric, k=10, query roles and numerical/recall criteria stay fixed. The guard uses dedicated persistent exact readers on the same exported snapshot. The timer includes both attempts and all serving guard/decode work. Setup, snapshot import, shared-map construction/attachment, warmup and close remain separate, explicitly reported lifecycle costs. No cached exact labels substitute for a serving SQL operation.

Parent selection changes from smallest adequate native-only effort to lowest measured complete guarded serving mean on development, equally weighting the six scalar conditions; within1% choose larger effort. Use only the existing fixed640/1000/2048/4096/8192 grid. The current module's effort ceiling is the already disclosed research extension; no new C algorithm or graph change is introduced. Preserve every grid candidate and result. The paired native/no-op A/B timing experiment is development evidence from one allocation, not the later confirmatory latency study.

A no-stop policy exercises the real agent decision/feature/continuation path with the same guard. Historical and forced policies provide runtime probes at the selected setting. Neither substitutes for the requested new agent episode; future proposed programs still need bounded feature validation, replay and live parity before validation selection. Before generation, independently verify this return and pin the selected parent/module/guard and corresponding baseline configuration. Reconcile provider usage then execute the already authorized bounded episode. No provider or held-out query request is launched by this kit preparation.
