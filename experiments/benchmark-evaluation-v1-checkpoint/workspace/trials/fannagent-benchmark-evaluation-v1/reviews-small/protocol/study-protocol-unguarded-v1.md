## Question, scope and claims

Can compiled agent stopping policies preserve the actual unguarded native640 recall, including its short outputs, while reducing complete approximate-search request latency? Compare with native640 and a tuned native baseline selected at matched native640 quality. Report absolute recall independently; preservation of low recall is not a high-quality retrieval claim.

Use the preserved original full HNSW graph, 247,286 rows, 768-dimensional cosine vectors, k=10, iterative scan off, serial persistent readers, and the published filters total_votes >= 743/527/310/192/108/32. Unfiltered is a separate control. Primary workload weighting is equal across the six scalar filters; report all seven separately. No predicate is silently omitted because it is difficult. A short valid result is scored normally, not a runtime failure. A genuine integrity/runtime failure invalidates qualification; narrowing scope requires a versioned protocol amendment before validation/test and a qualified runtime, not a post-result exclusion.

The primary recall claim is preservation on the fixed held-out benchmark workload. We do **not** claim population mean-recall noninferiority within 0.25 percentage points: 275 independent groups cannot establish that worst-case guarantee merely by exhibiting zero losses. Report any future-query inference separately with its explicit sampling assumptions.

## Recall scoring and inference

Recompute exact reference on the actual imported SQL representation on development. For each request force a sequential exact cosine sort with `FETCH FIRST 10 ROWS WITH TIES`; preserve self matches and source IDs. Validate unique returned IDs, filter eligibility, finite cosine distances and count no larger than min(k,eligible_count). Ground-truth self/tie and canonical-to-source-ID mappings must be qualified before reuse of published labels. Score returned eligible IDs at/below the exact kth boundary with absolute distance tolerance 1e-6, counting each ID once. Record boundary ties separately. The recall denominator is min(k,eligible_count), regardless of the number returned. Missing neighbors count as misses: seven true top-ten neighbors out of ten gives .7, not1. An empty eligible population has recall1 only with an empty result. A short answer is a scored outcome, including when fewer than k records exist. Duplicate, oversized, ineligible, nonfinite or malformed outputs remain integrity failures. No automatic exact completion or replacement is allowed.

Report per-condition native/candidate recall, paired difference, query-level losing groups and magnitudes, missing/invalid outputs, exact-tie diagnostics, and the overall vector-group count. Final preservation requires zero observed losses for every test group in each of the seven conditions against the declared reference. The .0025 margin is recorded consistently in recall units, but is not advertised as a population confidence result.

Report exact one-sided Clopper-Pearson upper bounds on loss probability per condition at alpha=.05; also simultaneous per-condition bounds using alpha=.05/7 and an any-condition-loss group indicator at alpha=.05. With zero any-condition losses among 275 groups the bound is `1-.05^(1/275)`, approximately 1.0834%. These calculations assume independent comparable query draws; the fixed published benchmark set and historical availability process do not themselves guarantee that sampling model. Repetitions and predicates are not additional independent groups. Do not use a zero-width bootstrap recall interval to claim universal safety.

## Latency experiment and controls

Exact sequential search is an OFFLINE EVALUATOR ONLY. Finish all exact reference queries, record their separate evaluation cost and close their connections before approximate quality/timing phases. Truth and expected labels may score outputs outside timers but are never supplied to the serving function or compiled rule. Never append/replace an ANN answer using reference IDs.

The primary endpoint is the arithmetic mean unguarded complete approximate-search request time on an already open reader: SQL binding/dispatch, feature collection, policy evaluation, ANN and continuation, fetching and decoding. Keep setup, connection, lookup build/attach, warmup and close outside that request timer and report each separately. Preserve output validation for every timed request; perform heavy validation outside the timed interval and compare output identities to preverified quality records.

Run five independent compatible Torch allocations, each with four epochs, seven families and two identically coded A/B reader labels per family. Each reader/filter receives ten development warmup queries, followed by the full test group set; validation/test queries are never used for setup tuning. One reader per family/filter/label persists for its scheduled requests. Use 14-label Williams rows, rotating the base row [0,1,13,2,12,...,7] by allocation/epoch/group position, with mirrored epochs and mirrored paired query orders. Rotate filter order. Schedule seed: `reviews-clean-confirmatory-timing-v1`. Export the full executable schedule and its hash before test; maintain each query's cross-arm pairing and record reader identity and predecessor/order.

For each family/filter, identical-code A/B controls pass only when their paired hierarchical 90% two-sided mean-ratio interval lies wholly within [.98,1.02]. Every control relevant to a comparison must pass; pooling away a failing filter is not allowed. These equivalence checks form an intersection requirement, not a search for a favorable label. A failure makes affected performance contrasts inconclusive. Never subtract a control gap from treatment timing.

Analyze 20,000 paired hierarchical bootstrap draws, seed20261110: resample allocations then vector groups; preserve all filter, family, label and epoch observations for each sampled group. Report the ratio of equal-filter arithmetic means, absolute milliseconds, percentage reduction `100*(1-ratio)` and speedup `1/ratio`, with median and p95 secondary. Show every allocation's effect and node/CPU, and explicitly limit inference from five allocations, especially if all use one node.

The two primary latency contrasts are new agent/native640 and new agent/tuned-native. Each passes the practical target only if its one-sided 97.5% upper ratio bound is <=.95, controlling the two-comparison family at .05 by Bonferroni. Combined headline success requires quality plus both contrasts and their relevant controls. Passing only native640 supports the narrower stopping-intervention claim. Secondary scalar-filter contrasts use Holm across the twelve agent/native comparisons; unfiltered and other baseline comparisons are descriptive unless separately declared.

Five allocations/four epochs is a fixed feasible design, not a promise of sufficient statistical power. Report inconclusive intervals honestly. Before final test freeze, development evidence supplies precision projections but cannot change this count opportunistically; any justified redesign is a versioned amendment before validation/test. Do not accumulate additional allocations until success. Replace at most two infrastructure-invalid allocations with unchanged code; never replace a valid negative or statistically imbalanced allocation. Publish every invalid allocation and reason. Query omissions invalidate the allocation rather than silently reducing the cohort.
