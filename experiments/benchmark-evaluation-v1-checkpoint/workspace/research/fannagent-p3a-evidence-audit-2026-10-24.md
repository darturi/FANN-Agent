## Actual stopping outcomes: complete on the restricted action grid

The declared action space is **stop at ordinal checkpoint 1, 2, 4, 8, 16, 32, 64 or 128, or continue**. A checkpoint ordinal is not a distance-work budget or a training sample count.

| --- | ---: | ---: |
| Nominal query/checkpoint positions: 600 × 8 | 4,800 | 4,800 |
| Reached positions with actual stop proofs | **4,695** | **4,695** |
| Missing stop labels at reached allowed positions | **0** | **0** |
| Positions not reached because search finished | 105 | 105 |
| Allowed reached positions with all qualified features available | **4,695** | **4,695** |
| Measured complete top-10 stops | 4,665 | 4,665 |
| Measured incomplete top-10 stops | 30 | 30 |
| Stops with recall below their own native reference | 2,108 | 2,108 |
| Measured continue outcomes | 600 | 600 |

The **9,390 actual stop proofs** reproduce their exact observed feature prefixes and returned IDs/distances. Static and progress outputs match each other at all **4,695 corresponding stops**. Both regimes of each stop/continue outcome reconstruct from the recorded acquisition pairs: **21,180 retained pairs**, plus the historical discarded warmups. Native recall is 99.35%, 99.15% and 98.60% on unfiltered, `votes32`, `votes108`.

Each filter has 1,565 reached stop choices per profile. Checkpoints 1–32 are reached by all 200 vectors per filter; checkpoint 64 by 199; checkpoint 128 by 166. Thus the 105 unreachable positions per profile are three checkpoint-64 positions and 102 checkpoint-128 positions. They are not missing interventions on a reachable state, and must not be filled with invented stop labels.

All incomplete stops are known negative outcomes on `votes108`: **28 at checkpoint 1 and two at checkpoint 2**, per profile. Keep them in denominators and enforce complete top-10 when judging decisions. Missingness, invalidity and recall loss are different states; a favorable score must not be obtained by dropping any of them.

This coverage permits evaluating the first predicted stop of any policy restricted to the allowed grid and qualified information. It does not demonstrate that any trainable policy can choose sufficiently safe and useful stops.

Light19 observation traces match the projected static traces, and its executed stop outputs match the corresponding static outputs. That correspondence does not manufacture unexecuted Light19 interventions or collection costs.

Acquisition timings are **fixed-stop proxies**. They preserve the source profile's measured collection and query work, but do not execute a newly fitted tree's observation/interpretation behavior or establish its complete composite-session admission and routing cost. Do not transplant static23 costs into a cheaper Light19 claim, pool old/new binary timings, subtract P2 savings, or use P2c conditioning results as original-scope serving latency.

## Qualified features and information limits

All relevant getter qualification records pass: base19, static23 and progress34 on the current module. Their group composition is:

| Profile | Available decision information |
| --- | --- |
| Light19 | Existing checkpoint, work, queue and distance observations |
| Static23 | Light19 plus actual predicate threshold and bounded local-probe examined/passed/ratio |
| Progress34 | Static23 plus eleven bounded layer-zero progress observations |

All qualified values on the allowed reached grid have valid declared types, finite numeric values and no missing observations. The current corpus also contains these fields throughout its recorded full trajectories. This availability finding concerns the observed workload, not a guarantee for future empty queues or other inputs; availability guards remain required.

The audit independently reconstructs all eleven progress observations over **95,106 states**, using only metadata rows/windows observed by that checkpoint. Recorded SQL metadata/distance receipts and the fixed per-window/every-query fetch limits agree. Defined empty-sample zeros retain counts and `progress_has_valid`; they are feature semantics, not imputed stopping outcomes. The original qualification tests remain historical native evidence; this audit does not execute new getter tests.

The static probe statistics are unchanged throughout all **600 trajectories**. Progress features change between eligible checkpoints in all **600 cases**. This establishes recorded information availability and variation, not predictive benefit or a favorable cost tradeoff.

There is also a concrete aliasing limitation: the projected Light19 trajectories for `votes32` and `votes108` are identical for **all 200 vectors**. Yet **359 of 1,565 paired measured grid states**, spanning **139 vectors**, disagree on the descriptive target “complete top-10 and recall at least this query's native recall.” A shared tree using only those identical Light19 observations cannot distinguish those paired states. This is not an impossibility result for selective host routing or a proof that no useful Light19 policy exists. Static23/progress34 already expose the actual validated predicate threshold, which can distinguish the filters without adding evaluator-only identifiers. [Feature diagnostics][diagnostics].

Learners must not receive query IDs, vector-group IDs, source roles, future states, exact truth/recall or outcome metadata as runtime features. Those values remain grouping, labels or audit metadata. The legitimate threshold feature comes from the validated query predicate; an evaluator stratum is not a substitute serving input.

## Exposure and evaluation boundaries

Float32 vector hashes verify **200 unique vectors** with three filter variants each. The pool consists of 100 original-learning, 60 additional-learning and 40 formerly calibration vectors. Every one is already exposed to earlier research. Existing five folds contain **40 vectors each**, with every vector's filters together. Do not call the former calibration group fresh validation, count the older 100 again, or treat checkpoints/repetitions/filters as independent samples.

Metadata-only checks show the 60 unexecuted confirmation-vector hashes and 37 reserved-vector hashes are disjoint from the exposed pool. Their query values and outcomes were not opened. The earlier consumed confirmation remains consumed and excluded. Grouped folds can prevent direct leakage in a future development comparison; they cannot erase historical design adaptation or establish independent confirmation.

## Coverage decision and next step

**P3a coverage gate: pass for the restricted static23/progress34 development task. Final G3 family selection remains unassessed.** We have enough existing actual outcomes and qualified information to ask whether a flexible predictor can exploit earlier-stop information that the bounded shallow policy misses. Additional outcome collection is not the immediate dependency.

Prepare **NEXT-MODEL-01 / P3b** next, with these requirements frozen before fitting:

1. Restrict both methods to the same qualified profile/information and the same eight ordinal checkpoints plus continue. Keep all filters, invalid outcomes and full first-stop trajectories. Compare flexible versus deployable shallow decisions within each profile; do not attribute different collection scopes to model capacity.
2. Preserve vector-group folds and separate fitting/model selection from held-out development scoring. Any thresholds, preprocessing and hyperparameters must use training groups only. State prior exposure and the limits of the resulting intervals.
3. Freeze the recall/complete-result objectives, finite model/search budget, reference baselines and owner/reviewer. Report coverage before scores. Treat fixed-stop cost/physical-work outcomes as diagnostic proxies; no predicted latency result establishes deployment benefit.
4. Distinguish outcomes: flexible succeeds/shallow fails → representation/compression question; both fail → inspect information/risk/diversity under the bounded tested family; neither result proves a universal ceiling. G3 requires that evidence-supported family decision, not just model execution.
5. Only if a result justifies it, prepare a separate targeted measurement contract. A current-binary full Light19 study would need the missing 3,621 actual stop choices reconciled and compatible costs acquired; an off-grid policy needs actual outcomes at its newly allowed choices; a new deployable policy needs actual full-path latency and native proof. No such acquisition is assigned by this audit.

**No Torch command is needed now. No model has been fitted.** Original execution stays adopted; P2a/P2b remain experimental, P2c's conditioned result stays scoped, and the closed selective episode is not resumed. The [roadmap][roadmap] records completed P3a tasks and the new modeling-contract dependency.
