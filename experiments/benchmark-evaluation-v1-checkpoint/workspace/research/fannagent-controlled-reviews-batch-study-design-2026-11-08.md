# FANNAgent controlled Reviews batch study design

November 8, 2026

**Frozen design for one development study.** Test whether one agent-proposed policy lowers end-to-end time over the fixed ten-query Reviews batch while preserving recall against ordinary full-graph native `ef_search=640`. The benchmark scope is the 60 declared batches on exposed data. The session endpoint is prospective for this study. The earlier activation and reuse verdicts stand. ## Paired session measurement

Time six labels per manifest session in each of two serial timing epochs in the same allocation. Labels `0–5` are `native-A`, `native-B`, `seed-A`, `seed-B`, `candidate-A`, `candidate-B`. Identical labels within each family use the same execution factory and artifact. Run one arm at a time with a fresh private reader. For zero-based manifest block `b` and session rotation `r`, add `(b + 2r) mod 6` to `[0,1,5,2,4,3]` modulo six for epoch one. Follow manifest session order. For epoch two reverse the session order and reverse each session's arm order. Both epochs retain the same ten requests in the same order inside every arm.

Start the outer timer before reader acquisition and binding. Include session construction, all ten requests and reader close. Charge lazy compilation and installation on the first eligible request, even when the first request bypasses. Keep all routing, SQL, transport, decoding, and reuse work inside the endpoint. Use one successful binding per arm, one request in flight, and unchanged 30-second statement timeout. Each later arm starts with an empty prepared and installation state. A reader failure, fallback, unexpected reconnect, reset or mid-session reinstall invalidates the measurement and retains charges. Verify every timed output against its untimed proof. No per-session warmups or conditioning searches. Record common restore, snapshot and qualification separately as campaign work. Shared database buffers may warm across arms. Report first-request, first-eligible and per-position timings alongside total session time.

For each family, require both two-sided 95% A/A intervals to lie wholly within **±0.10 ms per request** for `(total_B − total_A) / 10` and **±log(1.02)** for `log(total_B / total_A)`. This preserves the absolute margin at the request scale while charging all batch setup in the totals. For the primary candidate contrast, average the two identical labels within each family and paired session and epoch. Use the mean of `log(candidate_total / native_total)` across sessions. Require the upper endpoint of its two-sided 95% interval to be **below zero** and arithmetic mean savings in both epochs. Bootstrap the 20 disjoint manifest vector blocks with all three sessions, both epochs and all labels together, 10,000 draws and seed 20261019. Report direct seed versus native and candidate versus seed contrasts as secondary evidence. No control subtraction, selective pooling, or additional epochs. A/A failure yields `measurement_inconclusive`. A joint pass is a development qualifier for this controlled batch. The internal clock covers restore and preflight up to 1,500 s, untimed qualification and quality up to 2,700 s, timing up to 1,800 s, and a reserved 600 s for final integrity, sealing and cleanup. Cap reader startup at the original security query, target bind, 14 pinned settings and statement timeout plus one read-only binding and settings verification query per reader. Account separately for restore and verification SQL, exact-reference support, tracing, and installation. These ceilings require local lifecycle and timing-path validation before release. Deadline, limit, identity, budget, coverage, archive or cleanup failure closes the attempt. No restart, automatic retry or reuse of unused stage counts.

Any later proposal allowance is capped at two Mac-side provider attempts and $6 total, one export and zero fits. Reserve charges before each request. Use a second request only to continue a successful first response, with no retry on failed or uncertain calls. Retain the original sandbox ceilings of two CPUs, 4 GiB, 120 commands and 3,600 active seconds. The native package has zero provider access. This design authorizes zero calls and zero allocations.

Before any handoff, implement and locally verify an isolated harness for reader ownership, fresh policy state, exact operation accounting, failure and cleanup, ordered proof parity, timing capture and independent saved-data reconstruction. Require a strict sealed package, protected before/after pins, final data and graph checks and a complete locked raw return. Retain exact discrete parity and `1e−12` floating tolerance.
