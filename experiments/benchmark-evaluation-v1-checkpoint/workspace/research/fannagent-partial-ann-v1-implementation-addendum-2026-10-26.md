# B2d implementation addendum — before implementation and measurement

Frozen October 26, 2026. Supplements, without editing, the [partial-ann.v1 design](fannagent-partial-ann-v1-design-2026-10-26.md). The user authorized isolated implementation, local correctness checks and preparation of the Torch handoff. No Torch submission or native experiment is performed locally.

The 200 cases, 16,802-search ceiling, two-copy intervention, quality/A/A/economic gates and single three-hour allocation ceiling remain unchanged. These implementation details make the resource and failure contract concrete:

1. Keep the inherited 30-second reader statement timeout. Never dispatch a search unless at least 30 seconds remain in its stage and the work allowance before the 600-second finalization reserve. A stage alarm cancels blocking administrative work; the build has a server statement timeout bounded by its remaining stage allowance. This can stop early and cannot extend a stage or add a search. Finalization has its own bounded 600 seconds inside the global allowance.
2. Run the site's read-only `myquota` check before `sbatch`, and repeat it on the compute host before restoring. Parse scratch and home space/inode limits conservatively, allowing for display rounding, and compare scratch with the design's two-copy formula and home with 3GiB/10,000 free inode headroom for evidence and its archive. Also check filesystem free bytes/inodes. Unknown output or insufficient quota fails before reservation/submission when detected at login, or fails qualification on the compute host. No assumed default quota is substituted. Source: [NYU Torch utility applications](https://services.rt.nyu.edu/docs/hpc/tools_and_software/utils/).
3. Both private servers retain inherited shared_buffers=128MB/max_connections=16 and original query GUCs. Before building, persist their actual settings and a conservative memory allowance including four work-memory consumers per maximum connection, snapshot/client/build reserves and server overhead; it must fit 32GiB. This is a preflight bound, not a measured peak-memory guarantee; Slurm accounting remains authoritative.
4. Log every search, observer and explicit startup statement, including an attempt that raises, with operation, stage and containing monotonic times. Persist catalogs before validation and incremental checkpoints/charges on failure as well as success. Limit finalization helpers separately so expired acquisition does not prevent cleanup or evidence collection. Whole-run observer cap remains20,000, truth-helper cap4,040 and startup cap1,000; no uncharged search.
5. Keep `frozen/` byte-identical to the previous verified package, including its full three-context input file, because its manifest is a protected identity. Add a separate selected200-case file and sealed schedule derived only from the >=108 subset. Never execute the other400 cases. Copy prior support modules into the new isolated package rather than modifying/importing mutable prior experiment directories at runtime.
6. Native baseline and partial-index outputs must remain stable as ID-distance mappings across repeated calls; arbitrary tied-distance ordering may differ. All outputs are independently rescored against the complete truth membership/tie boundary and frozen eligibility. Candidate approximate IDs need not equal native640 IDs. Compare raw remote/local reports with proven submission identity rather than container mount paths.
7. Host verification has a480-second alarm within the allocation's600-second host margin. The container work allowance starts before restore and is bounded to10,200 seconds including the finalization reserve. Failed/partial campaigns remain collectable only after terminal scheduler proof, with no automatic resume/retry. Collection/analysis is a separate, bounded data-only step, not additional measurement.

These details are prospective. Mock checks exercise the implementation; only the future native run can establish catalog/plan/module compatibility, index construction, recall or performance.
