# A3 exact-vector startup-memory harness

This is a distinct, once-only startup/admission resource experiment. The original
A2 tree and the five natively qualified A3 producer/consumer files stay unchanged.
All earlier allowances are spent. This experiment performs zero ANN/exact searches,
provider calls, fits, plan packets or request executions.

The original resource contract remains byte-identical: one hour, four physical
CPUs, 32 GiB, one snapshot and four full data-verification scans, 200 admission-only
requests, ten reader admissions with at most six live readers, both fixed creation
orders and five-second holds. The snapshot and every shared alias remain retained
through the final verification scans. No early root release, forced GC, cache
subtraction or skipped integrity work is permitted.

The conservative pass condition is the largest recorded aggregate cgroup peak
across visible finite ancestors plus 2 GiB reserve plus 2 GiB workspace within the
effective limit (at most 32 GiB), with no positive limit/OOM event. Missing coverage
or insufficient margin closes inconclusive. A scoped startup pass does not qualify
workload memory, quality, A/A, speed, causal savings or full B2f.

The harness relocates the complete original main reference read-only under
`reference/`, with the unchanged A3 code under `a3/`. A strict native proof gate
consumes the authentic 128+128 and 56+56 case receipts and their independent audit.
Exact interpreter/private-hook/library provenance, source origins, byte hashes,
canonical literal parity and the metadata adapter preflight run before DB restore.

Actual reader admission supplies frozen metadata lists, while the qualified A3
producer expects an ordinary list. The separately frozen bounded adapter returns
an ordinary metadata view only after exact canonical-byte equality (at most
16 KiB). It restores the original store getter before returning that first read,
which precedes the producer connection. The immutable reader origin/state and all
vector, row, SQL and constructor code remain unchanged. This boundary was found
by the new full runtime fixture; earlier native producer receipts are not claimed
to cover the adapter. The fresh resource job tests the combined path.

Host preflight is at most 240 seconds, container work at most 3,000 seconds
(including the original 600-second guest cleanup reserve), and host post work at
most 240 seconds. Child termination, reaping and sampler stop consume that post
phase. The full 120-second outer margin remains reserved. Deadline expiry prevents
further heavy verification; failure or unknown dispatch never permits a retry.

Local checks use the actual frozen backend, producer, constructor, eligibility,
admission and runtime entry with at most 64 synthetic rows and simulated SQL.
Host/scheduler transports are fake; complete-count replay proofs are metadata
only. All external connection/process calls are blocked. Source and sealed checks,
full source/member/archive hashes, original-file preservation and the final
release audit must pass before a Torch handoff.
