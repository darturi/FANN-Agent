October27,2026 America/New_York. NEXT-STARTUP-RESOURCE-01 / startup-resource.v1.

## Question and fixed boundaries

Can the unchanged full-size snapshot, exact identity checks and ten-reader
admission lifecycle complete in one declared4CPU32GiB allocation, and is a
conservative total-charge margin demonstrated? Keep original data, both retained
full/partial graphs, module, image, settings and policies unchanged. Restore two
independent whole stopped-cluster copies from the retained B2d work; original
sources are read-only and never started. Missing/changed source stops the run.
Three failed calibration allocations stay spent; the new name/reservation denotes
one additional allocation. No automatic retry or automatic calibration follows.

**Exactly zero ANN and exact searches.** No native/exact reference, qualification
search, priming, conditioning, warmup, measured burst, EXPLAIN, quality/bootstrap,
policy fit or provider/protected query is allowed. Real SQL performs full data
verification, one snapshot scan, catalog/settings checks and reader admission.
The200 existing exposed requests are validated, never executed. Enforce zero at
private backend search entry points, operation reservations and an exact SQL
allowlist that rejects unknown/distance/order-by-vector statements before driver
execution. Record allowed SQL identities/counts and prohibited attempts.

## Memory observations

A separate owned host sampler runs outside Python's snapshot/GIL, before host
validation through final cleanup. Same Slurm step; record its CPU cost and
explicitly include its charge. Pin sampler/admin/postmasters to C3, client C0,
cell readers C1/C2 with epoch swap, same four physical-core admission rules.
No performance comparison is made under this instrumented resource regime.

Discover actual cgroup version from /proc membership and mountinfo. Resolve
mount-root-relative paths safely, enumerate at most16 visible ancestors and
record every finite limit plus root/unlimited values. Verify parent host process
and sampler membership; record container /proc cgroup/mount identity for analysis.
Do not assume a job-number path or cgroup/v2 from login configuration. Support
v1 memory usage/max_usage/limit/stat/failcnt/oom_control and v2 current/peak/max/
stat/events. Swap/PSI and optional absent fields have explicit availability.
Missing basic counters/mapping fails closed before expensive startup; unsupported
peak/event coverage can complete diagnostically but cannot pass the margin gate.

Sample once per second plus first/final observations; at most3600 samples,
500000 proc/cgroup file reads,512MiB bytes read,64KiB per file,256MiB sampler raw,
60 CPU seconds,32 live task-member PIDs. Identify each PID by start ticks and
cgroup membership; disappearing processes are recorded, replacements never
silently merged. Observe process VmRSS/VmHWM and cgroup aggregate/anonymous/file/
kernel/swap/pressure/event values where available. Track phase using atomic
progress files. Gaps above5s or insufficient startup/lifecycle bracketing mean
resource-margin inconclusive. Health failure requests bounded cleanup; no search
can run while monitoring fails. Read-only observations never change cgroup knobs,
drop caches, reclaim memory explicitly or touch unrelated jobs.

## Decision gates fixed before observations

G0 requires exact source/copies/catalog/data/snapshot/module/settings identities,
complete declared admissions/orders, zero searches/prohibited attempts and safe
cleanup. Incomplete/error outcomes have no positive resource verdict.

For a complete run, compute a deliberately conservative total-charge decision:
compare the largest aggregate kernel-reported peak across all observed finite
ancestors with the smallest observed finite limit, capped at the declared32GiB.
Require peak+2GiB safety reserve+2GiB outstanding workload allowance≤that limit.
All required observations/peak/event coverage must be present, limits/membership
stable, sampling gaps≤5s, and no positive limit/OOM/fail-count delta. Accounting
peaks may include unrelated siblings at a visible ancestor; this can prevent a
pass but must never create one. Components are descriptive and not added as if
independent or subtracted from peak. The2GiB workspace amount is a prospective
budget allowance, not a proof of any future search workload's maximum.

Outcomes: startup_resource_margin_pass_scoped, startup_complete_resource_margin_
inconclusive, or failed_or_incomplete. A cache-inclusive peak near32GiB is
inconclusive for this conservative margin even if startup completed. It does not
prove OOM or require memory expansion. The breakdown informs later review;
no post-hoc cache discount, new margin, repeat, larger memory, speed or adoption
claim is permitted. A scoped pass establishes this startup envelope only;
full calibration remains held pending its own resource/release review and all
unchanged native/quality/A/A/final gates.

## Local validation, release and trusted return

Before commands are released, exercise the actual launcher/host/runtime entry
points with synthetic OS/DB interfaces and actual frozen constructors/binding/
snapshot methods. Cover all three historical failure mechanisms, eligibility
schema/data/field negatives, startup/epoch/final/cleanup failures, guard rejection
before native SQL, v1/v2/mount-root/ancestor resolution, missing/invalid/changed
limits/counters, sampler lifecycle/health/gaps/caps/PID reuse and independent

mocked SSH/SCP/MFA failures and once-only reservation/uncertain dispatch.
No real DB or ANN/native experiment, provider, fit, SSH or protected query runs
locally. Full-size ID/vote-only fixture does not measure full-size memory.

Seal a new immutable package only after source checks; run sealed checks, static/
shell/AST, archive/member/scientific byte parity and prior-file preservation.
Transfer verifies both transport hashes and final remote files before success.
Terminal failures remain collectible. Trusted local code validates checksum,
archive paths/members/raw locks/submission/scheduler/package identities, all zero-
search SQL/admission/snapshot/source/cleanup and memory evidence, then reconstructs
resource decision. It never executes downloaded code or reports ANN performance.
